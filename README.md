# ناروَن — فروشگاه آنلاین لوازم تحریر

این مخزن شامل فرانت‌اند استاتیک سازگار با GitHub Pages و اسکلت بک‌اند امن مبتنی بر Supabase است. **GitHub Pages به‌تنهایی دیتابیس یا سرور امن اجرا نمی‌کند.**

## امکانات بک‌اند اضافه‌شده
- `supabase/schema.sql`: جداول محصولات، سفارش‌ها، مدیران و تنظیمات + RLS؛ سفارش‌ها برای عموم قابل خواندن/نوشتن نیستند.
- `admin.html` و `admin.js`: پنل ورود با Supabase Auth، فهرست سفارش‌ها، تغییر وضعیت، تنظیمات کارت‌به‌کارت و خروجی CSV. مسیر پنل مخفی نیست و امنیت آن متکی به احراز هویت و RLS است.
- `supabase/functions/create-order`: ایجاد سفارش با اعتبارسنجی سمت سرور.
- `supabase/functions/submit-transfer`: ثبت شماره پیگیری کارت‌به‌کارت؛ وضعیت پرداخت فقط پس از بررسی دستی مدیر باید به «پرداخت تأیید شد» تغییر کند.

## راه‌اندازی بک‌اند (رایگان تا سقف طرح سرویس)
1. یک پروژه در [Supabase](https://supabase.com) بسازید.
2. در SQL Editor محتوای `supabase/schema.sql` را اجرا کنید.
3. در Authentication > Users یک حساب با ایمیل خودتان بسازید. شناسه UUID آن را در SQL Editor با این دستور ثبت کنید: `insert into public.admin_users(user_id) values ('UUID-حساب-مدیر');`
4. در Project Settings > API، **Project URL** و **anon/publishable key** را بردارید. این دو مورد محرمانه نیستند؛ `service_role` محرمانه است و فقط باید در Secrets توابع Edge بماند.
5. با Supabase CLI، توابع `create-order` و `submit-transfer` را deploy کنید و Secretهای `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را از محیط پروژه تنظیم کنید. کلید service-role را در GitHub یا فایل JS قرار ندهید.
6. در GitHub Pages فایل‌ها را از ریشهٔ مخزن منتشر کنید؛ برای پنل، مسیر `/admin.html` را باز کنید، URL و anon key را وارد و سپس با حساب مدیر وارد شوید.
7. ابتدا با سفارش آزمایشی بررسی کنید؛ قبل از استفاده واقعی، توابع را به فرانت‌اند checkout وصل و تست ضداسپم/محدودسازی درخواست و سیاست حریم خصوصی را تکمیل کنید.

## کارت‌به‌کارت و پرداخت
شبا به‌تنهایی درگاه پرداخت نیست. راه فعلی طراحی‌شده برای **انتقال دستی** است: خریدار وجه را در اپ بانک انتقال می‌دهد و شماره پیگیری را ثبت می‌کند؛ مدیر پس از تطبیق مبلغ و گردش حساب، وضعیت را دستی تأیید می‌کند. هیچ‌گاه صرفاً با ارسال رسید یا شماره پیگیری، سفارش را خودکار «پرداخت‌شده» نکنید. برای پرداخت اینترنتی واقعی باید پذیرندگی در پرداخت‌یار/درگاه رسمی و callback سروری تأییدشده دریافت شود.

## امنیت و انتشار
- هیچ رمز مدیریت، توکن خصوصی یا service-role key را در HTML/JS، GitHub یا اسکرین‌شات عمومی نگذارید.
- از رمز قوی و MFA برای حساب Supabase استفاده کنید؛ دسترسی مدیر فقط با درج UUID در `admin_users` داده می‌شود.
- RLS را غیرفعال نکنید. در حال حاضر سفارش عمومی فقط باید از Edge Function ایجاد شود.
- Edge Functionهای نمونه اعتبارسنجی پایه دارند اما قبل از فروش واقعی به rate limiting، ضدربات/CAPTCHA، ثبت رخداد امن، بررسی دقیق قیمت و موجودی از دیتابیس و تست امنیت مستقل نیاز دارند.
- فرانت‌اند فعلی هنوز بخش‌هایی از سبد و پرداخت آزمایشی قدیمی را در مرورگر نگه می‌دارد؛ اتصال کامل checkout به Edge Functions و انتقال فهرست محصولات به دیتابیس، مرحلهٔ بعدی لازم است. این بسته را تا آن مرحله یکپارچهٔ آمادهٔ فروش تلقی نکنید.
- عکس‌های محصولات نمونه/گرافیکی‌اند. برای تصاویر واقعی از تصاویر خودتان یا تصاویر دارای مجوز استفاده کنید؛ عکس‌های فروشگاه‌های دیگر را بدون اجازه کپی نکنید.

## راه‌اندازی فرانت‌اند
محتویات این پوشه را در ریشهٔ مخزن GitHub قرار دهید و در Settings → Pages شاخهٔ `main` و پوشهٔ ریشه را انتخاب کنید.
